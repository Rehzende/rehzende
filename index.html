RCAI — Root Cause Analysis Intelligence

[PLATFORM] self-hosted · multi-agent · commercial-grade

A self-hosted platform that turns a raw alert into a structured, blameless investigation automatically — triage, evidence, root-cause analysis and postmortem, produced by a mesh of specialized agents an LLM orchestrator assembles on the fly.

What it does

An alert lands from Datadog, Prometheus, Grafana or OTel. The Go API normalizes it, links it to the affected service, and publishes it onto a Redis-streamed event pipeline. From there, a Python orchestrator reads the incident's context — the affected service's repo, pipeline, cloud resources, on-call team — and uses an LLM to decide which agents to call and in what order. That's a deliberate departure from a fixed pipeline: the routing is a runtime decision, not a hardcoded stage sequence.

How it's structured

Each agent — triage, evidence collection, root-cause analysis, blameless postmortem, plus a Kubernetes-debug specialist — is an independent microservice speaking Google's A2A protocol: its own Agent Card, its own endpoint, discoverable and callable without knowing its internals. Every run is tracked as a DAG (parent run, tokens, duration), visualized like an MLflow experiment, so an investigation's reasoning is auditable after the fact, not just a final answer.

Built the way it's meant to be trusted

Contracts before code, tests before implementation, and — because a lot of this gets built with AI agents working in parallel — a quality harness that's non-negotiable: nothing ships until the real build and test suite has been run by hand. That discipline has caught bugs no agent's own report mentioned — a call into a method a sibling agent had already refactored, a security fix that silently broke every internal caller that forgot to send the new required header, frontend routes calling backend endpoints that were never actually implemented.

Pulso

[PRODUCTION] fitness app · homelab-operated · k3s

A real fitness app — workouts, streaks, gamification — that I run on my own k3s cluster at home. Not a demo environment: real traffic, real load tests, real incidents.

Finding the breaking point

I pushed Pulso from 150 to 3,000 concurrent virtual users with k6 — not hammering reads, but simulating complete real workout sessions: start, paced heartbeats, finish. At scale, the app degraded exactly the way real systems do: database connection-pool exhaustion, requests queuing behind an idle-in-transaction write, latency climbing until readiness probes started failing.

What actually fixed it

  • Horizontal Pod Autoscaling (2→6 replicas, CPU-targeted) plus a right-sized connection pool per replica, kept under Postgres's connection ceiling.
  • Two real bugs under load, invisible until put under stress: a timezone-comparison crash on session close, and missing migrations that let live endpoints 500 silently in production.
  • A broken alert caught in the process: p95 latency alerts weren't firing above ~1s because of a histogram bucket ceiling — fixed before it could hide a real incident.

Closing the loop with RCAI

Pulso's Alertmanager alerts feed straight into an RCAI Kubernetes agent running on the same cluster. The moment something fires, it collects logs, traces and metrics on its own and runs them through an on-cluster LLM to produce a structured root-cause analysis — ranked causes, evidence, recommended actions — with no one triggering it by hand. It's RCAI's own reasoning, dogfooded on infrastructure I actually depend on.

How I use AI to build and operate

Not "vibe coding" — a discipline for using AI agents at real leverage without losing the ability to trust what they hand back.

01

Contract first

The interface or schema between two components gets defined before either side is implemented — so two agents (or two future engineers) working on opposite ends of a call can't silently drift apart.

02

Tests before code

The test is the spec. Implementation is done once there's something concrete to make pass — not the other way around.

03

Parallel agents, one verifier

Multiple agents can work disjoint files at once — that part scales fine. What doesn't scale is trusting a written summary of what they did. Every pass ends with the actual build and test suite run by hand, because that's what catches the bugs no agent's own report mentions.

04

Operate what you build

The same reasoning that helps design a system gets deployed to help run it — RCAI's Kubernetes agent watching Pulso's real alerts is that idea in production, not a slide.
